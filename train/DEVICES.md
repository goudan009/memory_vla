# 工作台设备

设备地址与路径统一在 `configs/workbench_devices.json`。不保存密码，使用本机 SSH 公钥连接。

- A100：原有多卡训练和推理，路径保持原状。
- 4090：原有 B1K 仿真评估。
- RTX 6000 Ada：`100.100.2.30`，单卡 48GB、128GB RAM。网页「启动训练」顶部选择设备，训练记录、源码同步、GPU 选择、排队、停止和续跑均按设备隔离。首页每 5 秒刷新显存与在线状态。

RTX 6000 Ada 的代码与环境在 `/data/projects/memory_vla`，数据在 `/data/datasets`，模型在 `/data/models`，训练输出在 `/data/outputs/memory_vla/training`。保留原有机器人及 Isaac Sim 环境。

先用单任务、GPU0、Microbatch 1–2 做开发训练；不同时开启独立验证（该功能需额外 GPU）。关闭验证会使全部 200 条示教参与训练，不能直接与使用 180/20 划分的正式实验比较。需要公平对比时，双方必须使用相同划分与训练预算。

网页训练、推理、评估均先选择设备，再选择该设备的 GPU。A6000 只显示 GPU0，不能选双卡模式。推理可在 A6000 加载本机训练权重；也可以连接 A100 已有服务。训练后点「用于推理评估」，设备、权重与源码会一并带入，不把 `/data` 权重路径误传给 A100。单卡先完成训练、释放显存，再启动推理与单环境仿真。

网页选任务后点击「准备所选缺失数据」：复制本机已转换的数据与 A100 登记的原始 Episode 划分，校验 200 个 Parquet 和 600 个三路相机视频后才标为就绪，不修改模型或动作格式。也可在 4090 执行：

```bash
python3 train/prepare_device.py --device a6000 --task 34 --dataset-only
```

设备离线时显示「离线 / 暂时不可达」，显存为未知，不将其误显示为 0。自动继续检查，上线后恢复展示。可选设备有独立监控线程，不阻塞 A100 / 4090 检查。断网不会远程停止已运行的训练；关机后需上线并从已保存 checkpoint 续跑，不会自动改投其他机器。

仿真使用独立 `envs/b1k2025-sim`，复制 4090 的 Isaac Sim 4.5 / OmniGibson / PyTorch 环境及原样资产，不使用机器原有 Isaac Sim 5.1/6.0。仿真资产在 `/data/datasets/b1k2025/simulation`，独立缓存位于项目 `cache/`。环境验收完成前，页面禁止启动；任务列表按已准备好的资产范围展示。

A6000 评估原始结果保留在 `/data/projects/memory_vla/evaluation`；4090 后台每 5 秒检查并增量拉回，目录为 `evaluation/V_几/方法/a6000_task几_eval几`，仍在同一个网页看进度、录像、暂停和续跑。断开设备连接时保留已同步结果，恢复连接后继续拉取。暂停按回合边界续跑，不恢复物理仿真中间状态。实时相机预览的远端同步有额外延迟。

## 代码维护：只在 4090 修改

两台远端的 `deployments/web_live` 是 4090 的单向发布目录，不在其中直接开发。同步范围包括 v1/v2/v3、Baseline 入口、训练、评估、脚本与配置；当前评估实际调用的外部 GR00T、OmniGibson、BDDL 源码也通过 `configs/workbench_sources.json` 纳入同一个摘要。

```bash
# 4090 执行：同步两台，并开启网页后台自动同步 / 离线重试
python3 train/sync_devices.py --auto

# 只同步其中一台
python3 train/sync_devices.py --device a6000
```

后台自动同步依赖工作台服务运行。网页的同步开关按设备保存；每次新训练仍会强制同步，之后复制为独立运行快照。新评估也使用独立快照。同步逐文件核对 SHA256，删除项仅清理上次清单登记的源码文件；不同步环境、资产、数据、权重或输出，也不改正在运行的快照。训练配置保存 `source_manifest.json`，评估设备记录保存 `source_digest` 与实际源码路径，便于复现实验。续跑保持原运行代码，不自动换成新修改的模型实现。

# 研究控制台：日常人机交互设计

日常入口见 [Agent 实验看板](agent_experiments.md)。

## 定位

解释版保留在 `/ai/architecture`，用于理解角色和固定流程。控制台原型聚焦研究全貌、执行透明度、阶段产物和控制节点。研究备注进入决策记录，运行参数通过方案修订更新。

## 信息层次

1. **研究总览**：任务数量、执行中、待审/异常、已归档；各任务当前阶段、责任主体、阶段进度与状态；待审事项与最近活动。
2. **任务控制台**：固定六阶段“方案、代码、资源、运行、评估、归档”，节点可跳转查看对应资料。阶段进度是已完成阶段占比，不冒充训练步数或耗时进度。
3. **结构化工作区**：研究方案、代码与审查、资源与执行、评估与结论、决策记录。右侧持续显示责任角色、运行约束、材料与产物追踪。

## 各阶段可见信息与操作

| 阶段 | 可见信息 | 人工操作 |
| --- | --- | --- |
| 方案 | 目标、判定依据、分支、控制变量、预算、协议、输入输出 | 批准方案、修订方案、管理材料 |
| 代码 | 实施任务、检查任务、独立审查、变更与检查证据 | 通过审查、退回修改 |
| 资源 | 设备能力、验证环境、数据/权重绑定、等待原因 | 确认资源并提交；冲突时保留排队或修订 |
| 运行 | 子任务依赖、状态、主体、输出、历史尝试与快照 | 暂停、恢复；前置失败后有限重试 |
| 评估 | 固定协议、指标口径、配对比较、数据来源 | 检查指标、核对运行身份；评估期间可暂停 |
| 结论 | 支持程度、局限、证据、后续方向 | 接受归档、要求补充实验（建立关联后续任务） |

AI 的行为以任务、阶段和事件呈现：谁在实现、运行了哪些检查、等待什么依赖、形成什么产物。避免用一段含糊状态文本代替执行过程。

## 版本与输入变更

修订目标、预算、协议、任务集合或关联材料会创建新方案修订，并重新审核。当前模拟运行如未结束会先转为暂停，原运行保留当时的方案、源码、资源与协议。归档结果不被新修订覆盖。新研究关联父任务。

决策备注独立保存，不触发代码修改、参数变更或新运行。调整参数必须使用结构化“修订方案”。

## 原型行为与真实接入边界

当前全部为前端模拟：材料、AI 实施、代码审查、资源分配、作业和指标均为示例。任务与记录存放 `memory-vla.research-console.preview.v3`，解释版 v2 数据保留不动。

人工批准、审查、启动、暂停与归档为正常界面操作；真实后台事件通过右上角“模拟后台状态”单独演示。训练产物就绪后进入评估；评估结果就绪后才进入结论验收。主页面不要求用户反复点击“下一阶段”假装运行。

“模拟前置检查失败”发生在训练预算消耗之前，标记消耗 0 步，最多重试 1 次。它只展示异常处理，不代表任意阶段失败都可零成本重跑；真实实现必须使用实际运行阶段与预算记账。

网页、AI 工具和执行服务仍按完整方案复用现有工作台，不新增训练实现。当前添加的后端改动仅用于静态页面路由。

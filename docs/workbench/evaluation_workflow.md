# 推理评估工作流与 N1.7 验收方案

## 页面职责
- 实验管理：版本、训练、Checkpoint、评估血缘；点击只选择。
- 推理评估：固定两个页签，运行总览、新建评估。提交成功后回运行总览；结果按钮明确定位到结果分析。配置预检通过才能提交，参数变化后重新预检。后端启动仍做独立校验。
- 结果分析：逐回合成绩、录像、失败备注、原始指标、配置及日志。不同 Benchmark 不混算成绩。
- B1K-2025：既有服务或启动推理服务，再设置任务、GPU、协议、回合、种子、实例。续跑与 Task40 工程诊断保留在模式选择内。正式评估与 fast-debug 分离。
- B1K-2026：原生 WebSocket 整体作业，独立启动/释放策略；不展示无关的常驻推理服务和旧 RPC 参数。

## N1.7 适配验收（当前，仅 Radio）
1. 环境、源码 revision、官方权重目录与校验值、任务 metadata、端口、设备就绪；不改变现有 whitelist。Task0 turning_on_radio，public-test ordinal 0–19，记录 evaluator 解析后的 instance_id。RTC off；单 GPU 单环境单回合。
2. 固定同一 public-test ordinal、官方权重、环境与协议，先完成一次有效 rollout。检查 server/evaluator 日志、实际 prompt、原生 action/state 接口、录像、success/Q 输出；进程正常退出不等于任务成功。
3. 对同一实例仅改变 language_mode（official_default / task_description），分别使用不同 attempt；不得将两者混为同配置。保留真实 prompt、权重 hash、源码、运行配置、原生 metrics、录像和错误。
4. 至少先确认可复现的有效闭环，并核对失败原因；如果官方权重效果不佳，先检查输入、归一化、动作映射、执行 chunk、环境实例与官方协议，不直接归因于记忆。原生是否成功单独报告，工程失败不算有效 rollout。
5. 扩展到 Task0/Task40 的自训 baseline 前，必须完成 N1.7 数据/训练/保存重载/闭环接口验收。任务与权重显式匹配；当前未实现的多任务、多环境、RTC、通用权重接口不得解除后端限制。
6. 正式科研评估另行固定公开测试实例集合、每实例重复、seed、任务指令、timeout、成功判定、动作执行协议、是否使用 RTC/历史。优先成功率及逐回合录像，Q-score 单独报告；不同协议不混合。正式 baseline、Memory、空/错记忆消融复用同一测试集合，明确不可用的能力。不得把调试的单回合当正式成功率结论。
7. 运行记录需固化 A/T/I/E 配置、checkpoint 身份及来源、实际实例、seed（可记录时）、任务指令、尝试号、状态、有效/失败回合、日志、录像、原生指标。缺失标记未记录，不从默认配置推断历史。

本次不修改 N1.7 运行器、训练器和底层仿真/指标协议；只统一工作台操作与验收约束。

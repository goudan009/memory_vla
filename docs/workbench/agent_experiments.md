# Agent 实验看板

在 4090 WYH 工作台打开「AI 工作流」。左侧扫描 `Output/test_NN/experiment_NN/`，包含 Test 01 与 Test 02。Test 01 保留原来的短链接，如 `experiment_01`。其他测试使用含测试编号的标识，如 `test_02/experiment_01`。运行进度显示各阶段、已归档的完成量和下一步，也显示属于该实验的实时评估作业。页面每 5 秒刷新。

将记录放到对应的 `Output/test_NN/experiment_NN/` 下。页面兼容已有的 `TASK.md`、`PROGRESS.md` 和 Experiment 07 的任务安排文件。每项都显示来源和文件更新时间。没有材料的栏目显示「未记录」。

公开入口见[实验文档索引](../../Output/README.md)。实验根目录使用 `README.md`、`task.md` 和 `report.md`。新报告默认被 Git 忽略，完成验收或封存（可含未达标项）后再显式暂存该文件；阶段报告不发布。历史任务书回填须注明依据。版本化计划继续按协作规则提交，其他工件留在实验存储。

## 先排计划，再开始任务

Agent 接到实验任务后，在本实验的 `workflow/plan-v001.json` 写明目标、主线、并行依赖和验收条件，提交到当前实验的 Git 分支后执行。接续任务先读取最新版本。调整步骤、依赖或验收时，复制当前版本为 `plan-v002.json`，更新日期和调整原因，保留历史文件。作业步数、回合数和状态更新写入 `progress.md`。

```json
{
  "goal": "按固定协议比较两个权重",
  "created_at": "2026-11-23",
  "author": "执行 Agent 或会话标识",
  "reason": "首版任务计划",
  "mainline": ["setup", "eval", "report"],
  "nodes": [
    {"id": "setup", "title": "锁定评估协议", "after": [], "acceptance": "固定实例、种子和判据"},
    {"id": "eval", "title": "配对闭环", "after": ["setup"], "acceptance": "归档两组独立回合"},
    {"id": "probe", "title": "机制诊断", "after": ["setup"], "acceptance": "归档固定输入对照"},
    {"id": "report", "title": "验收报告", "after": ["eval", "probe"], "acceptance": "提交指标与复现路径"}
  ]
}
```

`after` 写直接前置节点的 `id`。主线中的相邻节点须有直接依赖，闭环和诊断可并行，报告等待两者。进度表使用节点标题，已有不同阶段名时用节点的 `record` 指定对应行。`review_experiment` 可指向同一测试下的前置实验目录名。看板从其报告核对 `EXPERIMENT_编号_ACCEPTED=true`，执行 Agent 再核对证据并标记该节点完成。

打开「运行进度」可查看当前主线，点击节点可看验收条件、依赖、进度记录和已关联的训练作业。切换「计划版本」可查看旧流程及调整原因。历史版本展示当时的计划结构。

## task.md

```markdown
# 简短实验标题

> 摘要：用两三句写清楚验证目标、关键对照和验收标准。

## 验证目标

写下用户要回答的问题。

## 对照与验收

列出配置、控制变量、验收指标和预期产物。
```

## progress.md

```markdown
# 运行进度

> 当前动作：写一句当前正在做什么，或写明已经交付。
> 完成量：4/10 条已封存（填写核对时间和计数口径）
> 下一步：写明仍需执行或复核的工作。
> Agent Session：CloudCLI 会话 ID
> 机器：发起机器及实际执行设备
> 代码版本：提交 SHA 或工作台源码快照
> 配置：实际生效的配置文件或记录路径

| 阶段 | 状态 | 记录 |
| --- | --- | --- |
| 代码和配置核对 | 已完成 | 记录检查结果 |
| 推理服务就绪 | 已完成 | 记录设备和服务标识 |
| Run 01 正常历史 | 进行中 · 4/10 回合 | 记录工作台作业 ID 和输出路径 |
| 汇总指标和视频 | 待开始 | |
```

状态可用「已完成」「进行中」「待开始」「待验收」「未通过」「受阻」。将回合数和具体产物写在记录列，历史回填可用「记录依据」注明来源。文件时间表示记录更新时间。各次运行分别保留实际配置、作业 ID 和产物路径。

可加「训练作业」列，填写 `a100:训练运行名` 或 `a6000:训练运行名`。看板读取工作台作业和进度，验收状态由执行 Agent 在确认产物后更新。新尝试只更新作业绑定及进度记录。

看板也兼容实验 11 自动巡检的状态写法。只有回合数或已完成作业数时，归入「仅记录进展」，不计为正在运行或整个阶段已完成。

## result.md 和 report.md

`result.md` 是可单独编辑的简短结果。用「> 结论：」写一句结论，在表格中写关键对照值和口径，用「> 待验证：」补充未解决的问题。完整实验报告放在 `report.md`，网页可展开或下载 Markdown。

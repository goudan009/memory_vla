## 2. 架构与初始参数

### 2.1 三种互斥配置

| 配置 | embodiment_prior | 额外先验 | 修正分支 |
|---|---|---|---|
| A（默认先跑） | topology | 控制自由度邻接图 | 一层局部硬掩码 + 一层全局 |
| B | fk | 底盘参考系下关联连杆位姿 | 一层全局 |
| C | none | 不增加 FK 或显式拓扑 | 一层全局 |
| 归因补充对照（非首轮） | none + 两层全局 | 不用硬掩码 | 与 A 同宽、同深度 |

C 仍有静态属性、全身摘要和记忆，不能称作完全无本体先验。A/B/C 共同的模块、初始化方式、数据和训练预算一致。A 与 C 层数不同；严格归因时增加同深度对照。程序使用枚举值，不用 A/B 字母作为唯一身份。

### 2.2 建议首轮网络参数

| 项目 | 拟定值 | 说明 |
|---|---|---|
| 感知/认知槽容量 | 各 64 | 独立管理，有效槽位 mask |
| 感知特征 | 沿用 V1 视觉投影后、LLM 前的接口 | 三相机实际 token 数/维度以真实模型为准 |
| 感知槽视觉通道 | 256 | 优先复用 V1 压缩器；保留多视觉 token 存储 |
| 本体历史 | 原有归一化 q，保留有效物理字段 | 不单建库，不提前拓扑池化 |
| 认知特征 | 原 EOS 接口（2048 为当前记录值） | 不强制改 backbone 维度 |
| 认知检索 | V1 两层检索、Q/K 归一化 | 仅在认知分支保留现有融合方式 |
| 全身摘要 d_z | 128 | 共享小 MLP，每决策一次 |
| 自由度特征 d_b | 256 | 局部状态 + 静态属性 + 全身摘要；B 增加 FK |
| 检索投影 d | 256 | 点积使用缩放；两项评分尺度监控 |
| Value 维度 d_m | 256 | 初版每槽一个可学习摘要，原始多 token 在槽内保留 |
| 动作特征 d_a / 融合宽度 d_f | 256 / 256 | 从同一动作通道的 X 和 u0 取列 |
| 修正注意力 | 4 头，head dim=64 | A 两个 block，B/C 一个 block |
| FFN / 激活 / dropout | 512 / GELU / 0 | 小容量候选 |
| 联合检索权重 lambda | 1.0 固定 | 不新增可学习权重，记录两项 logit 标准差 |
| 压缩距离 alpha | 0.2 | 初始候选；视觉与本体距离须分别归一化到可比范围 |
| 记忆检索 | 全有效槽 softmax | 首轮不引入硬 Top-K |
| 修正输出 | 共享 Linear，输出 H，零初始化 | 保证加载时原速度场不变；首步梯度先达输出头，后续必须验证上游有梯度 |
| 空历史 | 直接跳过修正；历史无效 mask | 空历史回到原始速度场，不用非法 softmax |
| 历史读写 | 先读上一时刻库、当前特征写入一次 | 跨窗口保留数值，跨 episode 清空 |
| 反传边界 | 历史槽 detach，当前检索/Value/修正可训练 | 状态递推按相同截断规则；明确不对硬 merge 索引反传 |

压缩实现须优先继承 V1 的相邻合并与计数/时间维护，感知视觉与 q 同步合并。用归一化后的有效物理状态距离，避免 82 维中不同单位、重复特征、padding 主导距离。alpha=0.2 是建议初值；若距离定义尚未核对，不能直接写死。认知槽位使用增强后的认知独立压缩。

模型应保存真实张量维度，不能用 scratch config 的 16/29 替代 checkpoint 的实际 50/128。V1 文档报告 B1K 数据为 82 维状态、23 维有效动作；模型动作生成张量可能是 50×128。V1.1 的自由度修正只作用于有效动作通道（按实际映射 gather/scatter），其余 padding 不允许产生修正或计入损失。先从 checkpoint processor 和数据 meta 提取准确索引，不假设 q 第 j 项对应动作第 j 项。

### 2.3 物理先验映射（实现前必须核对）

- 静态属性：唯一通道 ID、控制类型、适用运动轴、范围及有效性 mask。位置控制和速度控制单位不能混用。
- A：根据真实 URDF/运动链建立通道邻接矩阵；自环有效，底盘/升降作为真实或虚拟根链关联，夹爪按物理关系处理；不能用数组顺序替代拓扑。全局层允许所有有效自由度交互。
- B：用已有可用关节配置计算基座系 FK，不把速度当位姿，不引入雷达/地图。位置 + 连续旋转编码；底盘和非关节控制通道设合理关联对象或显式无效 mask。不默认缓存历史 FK，不修改历史写入。
- A/B/C 保持完整的当前 q 输入原始 GR00T。新增本体特征只服务于历史检索及修正。

真实 URDF、状态字段映射、有效动作列、FK 参考系及模型/数据路径不在本文臆造，需在实际训练设备通过模型配置、数据 meta 与机器人资产核对并保存版本化描述。

## 3. 首轮训练协议（待用户确认）

### 3.1 目的与权重起点

首轮验证完整 A 架构是否可训练，以及正确历史是否能够改变 Task40 决策和动作。不是从头复现 50 任务，不是发表级数据效率实验。

初始化建议采用同一份官方已 B1K 微调的 GR00T-N1.6-BEHAVIOR1k 权重，仅加载原 backbone、原动作专家和原 processor。V1 记忆权重不直接迁移到结构不同的新双库/残差分支，避免旧 direct/residual 条件同时进入原 DiT。所有新增模块按同一固定种子初始化；冻结原分支。基线、A/B/C 使用相同权重文件 hash。实际本地路径以 workbench options 核验。

已 B1K 微调的起点可能已见目标示教，因此此实验衡量少量增量训练下的架构收益，不能当作从未见过 Task40 的少样本泛化证明。后续正式数据效率实验应采用共同的通用预训练起点或独立未见任务/真机示教。

| 参数 | 首轮建议 |
|---|---|
| 数据 | B1K-2025 Task40，官方 200 条成功示教 |
| 划分 | 固定 seed42，按完整 episode 180 train / 20 validation |
| 训练卡 | RTX 6000 Ada 单卡（实际空闲资源由工作台查验） |
| 精度 | BF16 autocast；可训练权重/优化器 FP32 |
| 冻结 | Eagle 视觉、视觉投影、LLM、原状态/动作投影、DiT、VLLN 全冻结 |
| 可训练 | 新感知/认知记忆、状态增强、B、检索、修正分支 |
| 学习率 | 1e-5，AdamW，betas=(0.9,0.999)，epsilon=1e-8 |
| weight decay / grad clip | 0.01 / 1.0 |
| 调度 | constant，首轮不做 LR 搜索 |
| seed | 42（初始化、划分、训练随机性分别记录） |
| 顺序训练 | stride=8 原始帧，最多32个决策/窗口 |
| 全局窗口数 | 1；最多32有效决策/optimizer step |
| microbatch | 2；最多16次累积，尾窗按实际有效元素归一 |
| 正式首轮预算 | 3000 optimizer steps（1000/2000/3000 保存） |
| 离线验证 | 0/1000/2000/3000；单卡顺序验证，不启用额外 GPU 异步任务 |
| 图像增强 | 沿用 V1 checkpoint processor 的训练增强；验证关闭 |
| 动作生成 horizon | 50（实际从 checkpoint 读取） |
| 有效标签 horizon | 32（按 B1K 模态配置和尾帧 mask） |
| 推理生成步数 | 4（沿用实际 checkpoint 配置核对） |
| 在线执行 | 前8步，30 Hz 原始协议 |
| 训练损失 | 原 FM + 状态监督；不加其他损失、不改原各部位权重 |
| 断点恢复 | 完整优化器/RNG/episode 游标及可恢复记忆状态，配置 hash 一致 |

V1 RETRAIN.md 记录 Task40 默认 180 条约 2368 个窗口；3000步×1窗口约一遍以上，实际遍历与尾窗统计以 loader 为准。1000步用于中间诊断，不能据此宣称完成全数据学习。训练资源不足优先降低 microbatch、不改变总窗口/预算；训练速度及显存不得凭旧模型估算为已实测。若需更大预算，另行确定，不自动续训。

V1.1-B/C 在 A 整体链路验收后分别从同一官方起点训练同预算；B/C 不从 A checkpoint 继续。若比较低数据条件，另设固定嵌套的50条训练子集，保持共同验证集并以实际见过的决策数/遍数和预算报告，不混用不同数据量结果。

### 3.2 状态监督是当前主要风险，不得原样复用旧 V2

[原 V2 实验报告](../../Output/test_02/experiment_01/report.md) 记录：200条示教完成对齐，仅 started 字段通过认证；正类稀少，1000步后 F1=0，预测事件0；12组配对恢复全部无效。旧版动作数值变化不证明正确历史有用。旧报告中 lambda 定标约 5.46e-5，不能直接作为新版默认。

首轮拟训练的任务状态优先为 door_open、bag_inside、started；仅使用经过认证的真实状态字段。bag_grasped 可后续加入，不作为首轮门禁。每个字段按原始 obs[t] 对齐，切换边界±8帧不确定标记 unknown；训练及验证均 mask 无效标签。不得把 episode 百分比充当状态真值，也不凭正样本动作推断每帧标签。缺失标签的字段不训练；若 door_open/bag_inside 未认证，则先完成标签核查，不能用仅 started 的训练宣称已解决开门与启动决策歧义。

初步损失建议：每个有效状态采用按训练集正负频率计算的 weighted BCE（正权重 n_neg/max(n_pos,1)，限制在 [1,20]；无正例字段禁止作为有效监督），按状态有效项平均。状态预测阈值默认0.5，报告每类 P/R/F1、事件检出与概率分布；不凭 accuracy 判断。若权重导致明显误报，用训练内校准，不在验证集事后改阈值来包装结果。

状态损失与 FM 尺度差异大，建议首轮默认 lambda_s=0.01 **作为候选起点**；正式训练前利用若干固定训练窗口核验共享认知增强模块上两项梯度范数，记录未加权与加权结果。若一项为零/非有限或比例严重失衡，停止并确定固定 lambda_s，再开始正式运行。不要训练中自动搜索或不断改权重。本项及标签认证是开发前/正式开训前必须确认的参数门禁，不声称现有证据已确定最优值。

### 3.3 冻结与残差诊断

默认冻结整个原 GR00T，避免微调破坏底盘/双臂能力；原分支 forward 可以无梯度执行，修正分支仍需正常反传。u0 不得先接入旧记忆；训练中历史只经新修正路径影响速度场。保存 step0、每个阶段的可训练参数数目与冻结权重校验、分部位 FM loss、梯度范数、修正幅度、P 行间相似度及状态分类指标。

若最终结果显示基线自身错误无法通过小残差容量纠正，再考虑解冻原动作专家并设置公平匹配对照，不在首轮同时改变冻结策略。冻结原模型不是已证实的最优训练方式。

## 4. 推理与评估

### 4.1 推理

新版本独立服务入口计划为 python -m v1_1_groot_memoryvla.serve；必须根据 checkpoint 恢复 prior、映射、容量、processor、归一化及 horizon，不接受不兼容配置覆盖。V1 serve 已有 model_path、embodiment_tag、device、host/port、history_mode 等接口，可沿用 RPC；实际参数在实现后通过 --help 与 workbench preview 验收。不能把下文当作当前可执行命令。

每次真实决策读取一次历史、缓存 B/C/m、生成4步（以 checkpoint 为准），每步只更新 X/J/修正量，最后写库一次。每个环境独立 reset，批量请求不混历史。推理 checkpoint 全量 strict reload，固定观测及固定噪声时保存前后动作一致。真实设备资源依工作台确认；现有工作台文档称 4090 的 local 入口用于仿真，推理服务支持 A100/A6000；不得假定 4090 已有新版本推理服务入口。小规模训练完成后先释放 Ada 训练显存，再在空闲的受支持设备上部署；仿真优先 4090，不抢占 A100 正式训练。

### 4.2 三层验收：工程、机制、正式闭环

| 层级 | 内容 | 验收 |
|---|---|---|
| 工程 | A/B/C CPU 单测、真实样本前反向、短窗运行、保存重载 | 张量/梯度有限、有效动作映射、无历史零修正、正确 reset、无重复读写、旧 V1 回归不变 |
| 离线机制 | 固定20条留出示教，预设每条5个机制窗口；同当前图像、状态、噪声、动作标签 | normal/empty/wrong 的状态、检索、残差与前8步动作差异及正确性；按 episode 汇总 |
| 正式闭环 | Task40 官方实例0–9各1个完整有效episode | 按正式协议报告 Q、成功率、Task Progress、实际 seed、有效/无效回合与视频 |

离线错历史来自独立同任务 episode，按进度匹配但保留语义冲突样本；重建认知状态和历史缓存，不能只置零一个 m 而保留其他历史旁路。另设固定配对的空/错历史诊断；空历史回到 u0 是结构性质，不代表正常历史确实正确。正常历史相较错误历史需要在目标决策或动作误差上呈现方向一致的改善。100个窗口不是100个独立闭环样本。

正式评估沿用 [公共协议](../../evaluation/evaluation.md)：
- 先固定官方 B1K 基线与 A 的相同实例/seed，默认 single1、base seed0、seed-mode=sequence、action chunk8、三路相机、原生 timeout/success、相同录像设置。用原始官方基线核对已有记录是否严格配对，否则重新评估。
- 主要仓库指标 Q Score，必须共同报告完整成功率与 Task Progress；研究判断重点看完整成功率和人工视频中阶段误切。不要用进度单独宣布方法成功。
- fast-debug 只检查接口与运动，不能混入正式成绩。此前 V2 的中途恢复 RGB 全部不一致，所以首轮从官方 episode 初始状态执行，不沿用无效的中途恢复配对。
- 后续 B/C 采用完全同一协议；首轮10回合可筛选明显差异，不能据此断言统计显著。需要精细区分时增加预先固定的配对重复。
- checkpoint 选择规则：首轮预先指定 step3000 为正式评估权重；step1000/2000 用于机制诊断，不事后挑最高成功率。若末尾工程未通过则不进入正式闭环。

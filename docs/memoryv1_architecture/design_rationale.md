# 表示差异与设计依据

本文配合 [架构说明](README.md)，对应 Task40 step4000 的 residual/value、scalar/EOS、每路64槽配置。这里区分源码事实、已有实验和设计推断，不将迁移适配自动解释为效果提升。

## 1. 两边的感知特征都来自视觉编码器

“原始特征”容易误解，应改为“视觉编码器输出，视觉语言投影之前”。MemoryVLA 并不直接存 RGB，也不是没有经过网络的特征。

```text
MemoryVLA：DINOv2 + SigLIP → 拼接后的视觉特征 ─┬→ SE → 感知记忆
                                            └→ 视觉语言投影 → LLM

V1：SigLIP2 → 空间重排 / 下采样 → mlp1 ────────┬→ SE → 感知记忆
                                             └→ LLM
```

两者都是 LLM 前的视觉表示。V1 的 mlp1 投影本身不等于已完成当前指令与图像的上下文融合；后者发生在 LLM 中。

| 数量 | MemoryVLA 常用参考配置 | 当前 V1 | 原因 |
| --- | --- | --- | --- |
| SE 输入通道 D | 2176，即 DINO 1024 + SigLIP 1152 | 2048 | 视觉主干及取特征位置不同 |
| SE 输出通道 D | 256 | 256 | 保留同类感知记忆宽度 |
| 感知 token 数 N | 256，16×16 | 243，即3相机×9×9 | 相机数、patch 网格及空间下采样不同 |

`[N,D]` 中，N 是空间位置数量，D 是每个位置的向量长度。动作专家维度不是 256→243 个 token 的原因；改变线性投影的输出宽度通常只改变 D。这里没有“必须让 V1 也有256个 token”的要求。

证据：[MemoryVLA 保存视觉特征的位置](../../src/references_code/memoryvla/prismatic/models/vlms/prismatic.py#L368)、[V1 extract_feature](../../src/v1_groot_memoryvla/model/modules/nvidia/Eagle-Block2A-2B-v2/modeling_eagle3_vl.py#L355)。

## 2. 单个有效 user EOS 与单个 EOS

两者在架构中的角色相同：抽取一个经过 LLM、看过当前图像与指令的末端 token，作为当前认知 Query。V1 并未因此新增一种认知机制。

MemoryVLA 常用 LLaMA 的 EOS 表示，宽4096；V1 使用 Qwen 对话模板中结束当前 user 消息的 `<|im_end|>`，宽2048。V1 通过 token id 151645 与有效 attention mask 定位，避免拿到 system 消息结束符、padding 或尾部换行。当前模板只有一个 user 回合，所以取最后一个有效该结束符。

区别不止宽度，也包括基础模型、训练得到的表示和 prompt 格式；但“单有效 user EOS”主要是在描述准确的取特征规则，并不证明它比原 EOS 更有认知能力。它也不是显式计划或额外的可学习 Query。

## 3. 残差没有取代两层交叉注意力

两层注意力负责“怎么从历史检索”；direct / residual 负责“检索后怎么接入动作模型”，是两个独立问题。V1 保留两层检索、门控和双库。

```text
MemoryVLA 风格 direct：当前 + 历史 → 两层检索 / 门控 → Fp、Fc → 动作专家
V1 residual/value：    当前 + 历史 → 两层检索 / 门控 → 历史读出 r
                                                            ↓
                        完整 GR00T 上下文 H ───────────→ H + correction → 原动作专家
```

MemoryVLA 的动作专家按自己的 P/C 条件接口训练。GR00T 的预训练动作专家则已适应完整的 LLM 上下文 H，其中包括上下文化的图像和文本 token。直接迁移时用“LLM 前的视觉特征→新 SE→新投影，加单个 EOS”替换 H，即使没有历史，也改变了原接口和表示分布。

已有同输入、同状态与同噪声的48个观测对照：原 B1K 的归一化 `MAE_first8=0.009489`；新 direct 模块未训练、无历史时为 `0.105142`，约11.08倍。这个结果支持“当前 direct 迁移破坏初始兼容性”，不能推出原 MemoryVLA 方法无效，也不能推出充分联合训练后 direct 无法恢复。

残差保留 H，并将新增输出投影 / 标量初始化为零，使模型初始行为与原 GR00T 一致。它适合当前“冻结原模型、只训练 Memory”的目标。真实 B1K 的32个观测、31次有历史检查记录显示初始化特征及动作最大差均0。此性质是接口兼容性，不是任务成功率结论。

direct 对照与诊断见 `git show 9fd762f:task2_memory_training.md`。[残差初始化验证](../../outputs/overnight_memory_task40_20261114/README.md#L53)。

## 4. 为什么进一步从 delta 改成 value

这是残差内部的另一个选择，不能与 direct→residual 混成一步。

设当前表示 x、两层 Transformer 的输出 q₂，门控 g 在代码中控制当前项：

```text
融合写回：F = g*x + (1-g)*q₂
旧 delta 读出：r_delta = F-x = (1-g)*(q₂-x)
当前 value 读出：r_value = (1-g)*A₂*(M Wv₂ᵀ)
```

q₂ 还包含当前 Query 的残差、LayerNorm 和 FFN，因此 delta 不等于“纯历史内容”。实验中，旧 delta 模型将历史特征清零、保留槽位与时间后，动作拟合改善仍然存在；一个观测的负当前项 RMS 为0.14285，检索项为0.04789。更广的分解也显示不能将拟合收益归于正确历史内容。

因此 value 候选从末层同一次注意力中，只取无偏置的历史 Value 加权消息，再乘历史门控。若这次读取的所有历史内容为零，该消息就为零；没有显式 `-x`，也不会通过 Value 投影 bias 凭空产生消息。Query 和门控仍由当前观测决定，所以它仍然是“当前观测条件下”的历史读出。

两层检索和融合 F 写回继续保留。这是为了使 GR00T 的新增动作修正更直接依赖历史内容，不是说原 MemoryVLA 中融合当前信息有错。原方法本就用 F 同时表达当前与历史，目标接口不同。

证据：[内容清零与分解、value 改动记录](../../outputs/overnight_memory_task40_20261114/README.md#L49)。这些记录不构成 residual/value 相对原 MemoryVLA 的充分性能比较。

## 5. 16 槽增加到 64 槽的依据

64 是本轮选用的起始超参数，不是已通过16/64消融证明的最佳容量，也不是残差接入、2048维或三相机强制要求的值。

可以解释的机制是：每路可分别寻址的时间槽更多，首次满库合并更晚，可能保留更多独立历史细节；这是设计动机的推断，不是已验证的性能原因。满库后两者都合并相邻且相似的槽，旧信息可以留在合并槽内，因此不能简单说历史跨度增加4倍。

代价是满库内容量增加4倍，同样 Query 数下历史注意力部分的计算和注意力矩阵规模约增加4倍；并非整个模型计算增加4倍。64槽也不等于64帧原图：感知每槽243个特征 token，认知每槽1个 token。容量与32决策的训练窗口是不同参数。

证据：[容量选择原记录](../../src/v1_groot_memoryvla/RETRAIN.md#L11)。现有材料没有证明64优于16，不应在图中标为已验证的“长记忆增强”。

## 6. 对外讲述建议

可用表述：“我们将 MemoryVLA 的双路记忆机制迁移到 GR00T。为保留预训练策略的完整上下文与初始行为，采用零初始化残差接口；进一步使用历史 Value 读出，减少残差分支仅修正当前特征的可能。视觉特征位置和 EOS 提取随底座调整，64槽是待做容量消融的实验配置。”

不要表述为“残差取代了两层检索”“MemoryVLA 直接存原始图像”“user EOS 是新的认知机制”或“64槽已被证明优于16槽”。

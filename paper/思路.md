研究主题：Embodiment-Conditioned Memory Retrieval（ECMR）

① Memory： 保存历史感知、语义与运动状态上下文。

② Body： 表示机器人运动学结构及当前运动状态。

③ Retrieval： 让机器人本体、任务和动作需求共同决定历史信息的检索与使用。

第一部分：记忆构建（Memory Bank）
技术内容： 以 MemoryVLA 的感知-认知双记忆机制为基础，利用 GR00T N1.6 的 Eagle VLM 提取历史视觉 Token 和认知 Token，经特征投影与压缩后分别存入记忆库。保留固定容量与相似度合并更新机制，同时为历史记录关联时间、底盘位姿及关节状态等元数据，并处理合并后的来源追踪问题。暂时不建立三维地图或物体级记忆库。
GitHub+1

通俗理解： 相当于给机器人增加一个笔记本，记录过去看到了什么、当时理解了什么，以及当时机器人在哪里、处于什么姿态。笔记太多时进行合并，但尽量不要丢掉重要历史信息。至于哪些笔记值得看，这部分暂时不负责。
第二部分：本体 Token 构建（Body Encoder）
技术内容： 参考 BodyVLA 的运动学 Token、拓扑感知注意力和关节属性编码思想，基于 URDF 构建机器人运动学图，将关节类型、运动轴、父子连接关系等静态构型信息，与当前关节状态、底盘运动状态及正向运动学计算的部件位姿共同编码为 Body Tokens。第一版作为独立本体编码器，暂不改变 GR00T 原来的动作 Token 组织方式。
Mitsubishi Electric Research Laboratories+1

通俗理解： 让模型知道自己长什么样、各个部件如何连接、当前摆出了什么姿态。比如左臂安装在升降机构上，升降机构又连接底盘，因此底盘移动会影响左臂和相机相对于环境的位置。这部分是让模型理解机器人自身，不负责保存历史。

需要特别注意：本体结构和机器人在世界中的位置不是同一回事。 前者主要来自 URDF，后者来自里程计或状态估计；我们可以同时编码，但不必建立环境地图。
第三部分：本体条件化记忆检索（ECMR）
技术内容： 这是论文的核心创新。利用 GR00T N1.6 动作 DiT 的隐特征、任务语义及第二部分生成的 Body Tokens，共同生成记忆查询向量（Query）。通过交叉注意力（Cross-Attention）选择第一部分记忆库中的相关历史信息，并利用门控残差融合注入动作 DiT，保留原有 Flow Matching 动作生成机制。重点研究运动学拓扑和当前运动状态如何影响历史信息的选择，而不是强制各关节只查询各自的记忆。
GitHub+1

通俗理解： 机器人准备移动底盘时，可能需要更多参考以前在哪里看见过目标；准备伸左臂时，可能更关注以前观察到的物体位置和当前手臂的运动关系；双臂协同时，又可能需要综合两只手的信息。不是给每个部件分配固定记忆，而是让网络根据当前情况学习查什么。

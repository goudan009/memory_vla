# V1 修复后的重新训练

本轮目标是把 MemoryVLA 的方法迁移到 GR00T。保留 Eagle backbone、原状态/动作编码器、AlternateVLDiT、动作解码器和 flow matching；修改记忆条件与训练数据流程。下文是新运行的协议，旧运行的配置与固定源码快照仍描述其实际行为。

## 本轮修改

| 项目 | 修复后行为 |
| --- | --- |
| 动作条件 | `direct`：感知记忆融合结果经线性投影到 GR00T 隐藏维度，和认知记忆融合后的 EOS 共同进入原动作头。感知 token 使用图像注意力分支，EOS 使用文本注意力分支，不再叠加到完整的原始上下文序列。 |
| 首帧 | 无历史时使用当前感知与 EOS，感知压缩器和接口投影仍能收到动作 loss 的梯度。检索模块在有历史时参与计算。 |
| 记忆容量 | 可通过 `--memory-length` 配置；新运行默认 64，网页提供 16/64/256。64 是本轮起始配置，不是对 B1K 最优容量的结论。容量独立于 32 决策训练窗口。 |
| 历史机制 | 保留双路记忆、两层检索、历史 Key 的时间编码、门控融合、融合特征 detach 写回及相邻余弦相似度 ToMe 合并。 |
| Episode 顺序 | 每个虚拟槽连续处理一个 Episode 的窗口，结束后才切换 Episode；每个 Episode 固定 rank 所有权。多任务仍按任务均衡轮转。 |
| 尾窗 | 保留每 8 环境步采样到的所有真实观测，包括不足 32 决策的尾窗和只有 1 帧的 Episode。超出 Episode 的未来动作标签 mask 为 0，不填充虚假观测到记忆。 |
| Loss | microbatch 和 DDP 均按有效动作元素数加权。不同长度尾窗和提前耗尽的 rank 保持一致的梯度同步次数。日志记录实际决策数。 |
| 图像增强 | 默认使用 checkpoint processor 的训练增强；每次处理窗口前重新增强并编码冻结 Eagle。同一优化步/虚拟槽的增强种子不随 GPU 数改变，包含 Albumentations 自己的 RNG。验证与 donor 数据使用独立的 eval 处理流程。 |
| 记忆验证 | normal/empty/wrong 使用同一个动作条件接口；empty 仅移除历史。wrong 来自独立的同任务训练 Episode，匹配目标记忆的时间槽并支持不同容量、短窗口。 |
| 保存与加载 | checkpoint 显式保存容量及接入方式。没有 `memory_conditioning` 字段的旧权重仍按 `residual` 加载。每次观测仅更新一次记忆，动作头四步生成不会重复写入。 |

## 启动本轮

使用现有正式入口 `train/run_groot_train.sh` 或训练网页创建**新运行**，从所选原始 GR00T 权重初始化。不要从旧 residual Memory checkpoint 开始 direct 训练，也不要对旧运行使用新源码做优化器续训。对照实验的 Baseline 和 Memory 使用同一份 GR00T 起点、Episode 划分、增强开关、学习率与全局窗口数；本轮的数据与增强改动也适用于新 Baseline。

原有启动命令增加以下参数即可；它们也是新运行默认值：

```bash
--memory-conditioning direct --memory-length 64 --image-augmentation
```

容量实验改为 `--memory-length 16` 或 `--memory-length 256`；关闭增强用 `--no-image-augmentation`。旧残差接口可显式选 `--memory-conditioning residual`，作为单独消融。global windows × 32 现在表示每步决策数上限，尾窗和空槽会使实际数量减少；Microbatch 仍只控制单次前向的决策数。

网页高级参数中已增加“记忆容量”“记忆接入方式”“启用训练图像增强”。启动前同步本次源码，并检查启动参数为 `direct / 64 / true`，使用新的输出目录。已有运行和排队任务使用提交时的固定快照，不会自动获得本次修改。训练、worker 和独立异步验证均传递相同设置；第 0 步验证从原始 GR00T 创建的新记忆模块也使用这些设置。训练协议记为 `memoryvla_direct_tail_v2`，其中 v2 是协议修订号，项目仍为 V1。

源码修改不等于已经在 A100 开训或部署网页服务。本轮没有启动训练或重启服务。

## 网页自动推荐参数

刷新 8765 工作台，进入“训练 → 新建训练”，保留“自动推荐参数”，选择任务、训练 GPU、方法和初始权重。推荐区位于表单最下方、启动按钮之前，默认只显示建议值；计算说明折叠在“查看推荐依据”中。网页根据 A100 上登记的真实 Episode 长度、训练划分、训练卡数及最小单卡显存，自动填写训练步数、学习率、全局窗口数、Microbatch、记忆配置、增强与验证设置。未选训练 GPU 等无法生成推荐的情况会显示具体原因，步数留空，不再保留旧的默认 3000。修改其中任一推荐参数会进入手动模式，刷新数据选项也不会覆盖手动值；“恢复推荐”重新应用当前选择的建议。

当前微调方式是冻结 Eagle，全参数更新动作头；Memory 同时更新记忆模块。LoRA 尚未接入，选项禁用，后端也拒绝该模式。自定义且未登记的模型、未完成数据准备的任务，以及小于 40 GiB 的训练卡暂无自动推荐，可先补齐信息或手动配置。

Task0/34/40 共 600 条示教、验证 10%、seed42、官方 GR00T-N1.6-3B 起点、80 GiB 训练卡的首轮建议如下。验证卡不计入训练卡数。

| 参数 | 2 张训练卡 | 3 张训练卡 |
| --- | --- | --- |
| 优化步数 | 18000 | 24000 |
| 学习率 | 1e-5 | 1e-5 |
| 全局窗口数 | 4 | 3 |
| 每步最多决策数 | 128 | 96 |
| Microbatch / GPU | 4 | 4 |
| 记忆容量 / 接入 | 64 / direct | 64 / direct |
| 训练 / 验证 Episode | 540 / 60 | 540 / 60 |
| 完整验证 / 权重保存间隔 | 3000 / 1000 步 | 3000 / 1000 步 |
| 图像增强 / 自动早停 | 开启 / 关闭 | 开启 / 关闭 |

这是起始预算，不是论文固定超参数或已验证最优值。每个 Episode 的窗口数为 `ceil(length / 256)`，其中窗口最多 32 个每隔 8 帧采样的决策，尾窗计入。当前默认划分的 Task0/34/40 分别有 1606 / 1775 / 2368 个训练窗口。推荐步数为 `向上取整至1000(任务数 × 最长任务的训练窗口数 × 目标遍数 / 全局窗口数)`：通用 GR00T 起点目标约 10 遍，B1K 已微调起点约 6 遍，项目已训练权重约 4 遍。后者学习率降到 5e-6，仍新建优化器，不恢复训练状态。任务等频轮转，短任务会多遍历；实际槽调度和尾窗会使遍数略有差异。非默认比例或种子使用按总长度估算的窗口数，页面明确标注。

全局窗口数取接近 4 且可整除训练卡数的值（1/2/4 卡取 4，3 卡取 3）；80 GiB 卡 Microbatch 取 4，40 GiB 档取 2。Baseline 与 Memory 保持相同预算便于比较。已有记忆权重沿用其容量与接入方式；本轮 direct 方法仍应从官方 GR00T 起点开始。

“检查配置”会核对真实数据、GPU 与权重，并展示最终训练参数；只有点击“启动训练”或“加入训练队列”才提交作业。完整验证间隔和早停开关已传到正式启动入口。长预算同时修复了逐窗口种子超过 NumPy uint32 范围时的异常；范围内的原随机序列不变。

## 验证范围

回归测试覆盖：双路记忆因果性与 detach、16/64/256 容量的分块/逐帧一致性、真实尾帧及动作 mask、任务/槽顺序、增强随机性与复现、normal/empty/wrong 控制、旧权重兼容、真实 GR00T 动作头训练和推理、Hugging Face checkpoint 保存重载、两进程 Gloo 梯度一致性，以及网页参数传递。

92 项相关回归测试已通过，包括两进程 CPU/Gloo 梯度比较和网页临时 HTTP 测试。动作头保存重载测试使用真实动作头及记忆代码、小尺寸配置和离线 Eagle 替身；新 direct 与缺少新配置字段的旧 residual checkpoint 都能重载且推理一致。

另在本机 GPU 1 完成真实权重检查：加载 `checkpoints/groot_n1d6_base` 原始 GR00T-N1.6-3B 和 Task0 示教，使用 direct/64、开启训练增强。两次真实观测的前向/反向 loss 为 0.1114547，全部 75 项记忆参数均产生有限梯度，融合条件形状为 `[2,244,2048]`。真实 Episode 尾帧 1952 仅剩 4 个有效动作，监督 mask 恰为 `4×23=92` 个元素，尾帧 loss 有限。动作生成形状 `[1,50,128]`，四步生成只写一次记忆。峰值分配显存约 17.11 GiB；本次检查没有优化器更新或模型保存。报告为 `/tmp/memoryvla_direct_smoke_20261111.json`。

这些检查覆盖实现正确性，不包含 A100/NCCL 长程训练或闭环机器人成功率。重训效果需由新一轮验证和闭环评估判断。

# V2 · Test 02 · Experiment 01｜任务状态引导的历史记忆

> 项目：Memory + GR00T（V2）
>
> 定位：V1（MemoryVLA + GR00T）上的**轻量任务状态记忆增强**，独立于 V3 的本体分角色检索；V4 再融合。
>
> 摘要：在 `Output/test_02/experiment_01/` 做一次方向探索与工程验证。完成 V2 实现、一次 Ada 小规模验证训练和一次集中评估。模型、测试、实验 ID 分别为 `v2`、`test02`、`exp01`。
>
> 训练、推理、评估、工作台资源调度、checkpoint、持续巡检、归档与复现均遵循 `robot-vla-experiment-ops` Skill。

## 0. 最终目标与边界

**要验证的科学假设**：历史记忆只依靠视觉相似性检索，可能混淆外观相近但任务状态不同的时刻。通过**可监督的任务状态预测**，使状态同时参与**事件记忆写入、历史检索和融合门控**，能否减少 Task40 的错误阶段切换，并使历史信息对动作产生可测量的影响？

V2 的交付物不是一套新的规划器，而是一条完整、可追踪的链路：

`当前观测 → 状态预测 → 事件记忆写入 / 状态条件检索 → 原记忆门控融合 → GR00T 动作生成`

**本次明确不做**：

- 不加入机器人评估失败轨迹作为训练样本；**只用 Task40 官方约 200 条成功示教**。
- 不训练额外大 VLM / LLM，不新建独立检索监督数据集，不设计检索对比损失，不引入复杂阶段规划器。
- 不修改 V3 的底盘/升降/左右臂分角色记忆机制；不提前实现 V4 的联合检索。
- 本任务只授权 Ada 小规模验证训练。后续如需 A100 四卡正式训练，另立任务并由用户确认 V2 架构。
- 不允许用 B1K 真值状态直接作为推理时的检索输入；真值只用于训练监督和离线评估。

## 1. 输入、版本和资源

### 输入

1. 与当前 GR00T 结构和数据协议一致的 **V1 checkpoint**，以及对应的模型配置、记忆库参数、训练脚本、评估脚本。优先使用已经完成对齐验证的 V1 权重；如果尚未产出或结构不兼容，必须明确标记为阻塞，**不能擅自换成不一致的权重并声称公平对照**。
2. B1K-2025 **Task40 官方成功示教（目标约 200 条）**、对应 observation/action 及时间戳。
3. 现有 Task40 仿真接口和评估脚本。之前保留的失败轨迹仅用于**诊断/评估**，不进入训练。

### 训练约束

- V2 训练与训练前自检使用单张 RTX 6000 Ada。推理和评估由工作台按可用设备和队列分配。当前可复用的组合是 Ada 训练结束后通过工作台提供推理，4090 做 Task40 仿真。调度时优先复用就绪服务并充分利用有余量的设备。
- 训练时默认冻结 GR00T 的视觉/语言主干和原动作专家，只训练本任务新增与现有记忆相关模块；保留从动作损失反向传播到**记忆融合位置**的梯度链路。

### 代码隔离

在src/目录下根据V1实现的代码，建立独立 V2 分支/工作目录，不可直接修改 V1 主线；保存起始 checkpoint 、commit、数据版本、训练配置及与 V1 的 config diff。

## 2. 模型实现：只改四处

### 2.1 任务状态预测（新增一个轻量 head）

- 从**当前时刻已有的 GR00T 表征**读取特征，预测多标签任务状态概率 `p_t`，不使用新模态。
- Task40 优先尝试的状态：`door_open`（微波炉门是否打开）、`bag_inside`（爆米花袋是否已放入）、`started`（微波炉是否已启动）；**最终字段必须由 B1K 实际可获取的仿真状态决定**，不得假定全部 API 已存在。
- 状态应描述**结果是否发生**，而不是机器人**是否尝试过**。例如“拉了门”不能当成“门已打开”。
- 不把任务简单压成一个随时间增长的进度百分比；允许状态保持不变、重复尝试及开关门变化。
- 用同一时间点的仿真真值 `y_t` 监督 `p_t`（BCE / 带有效字段 mask 的多标签损失）。

### 2.2 关键事件记忆（沿用 V1 记忆库）

- 继续使用 V1 原有记忆特征与记忆槽位预算，避免重新设计记忆编码器。
- 依据**预测状态的变化**（例如关→开、未放入→已放入），提升相应时刻的记忆写入优先级；保留少量近期普通历史，避免预测头早期不准时记忆库为空。
- 通过简单的置信度门槛/迟滞抑制相邻帧概率抖动造成的重复写入；**不增加事件分类网络或新监督损失**。
- 时刻 `t` 的观测用于预测状态和构造 Query。记忆检索只读取 `t` 之前已写入的槽位，当步检索和融合完成后再写入 `t` 的信息。

### 2.3 状态条件检索（修改检索 Query，不修改检索库主体）

- 以原 V1 的 Query 为基础，加入一个轻量状态投影，例如：`q'_t = q_V1,t + W_s p_t`（投影形状按现有代码实际维度适配）。
- 沿用 V1 `model/memory/bank.py` 的全库交叉注意力，保留原 K/V 组织、K 侧时间编码、检索层数与槽位预算。状态投影只加到计算注意力的 Query 分支，建议零初始化。保持原残差输入和后续门控路径。
- **无需给“正确历史帧序号”打标签**；检索投影依靠动作损失与状态表征的联合训练更新。
- 记录历史槽位的代表时间戳、注意力权重及对应状态。按权重排名可作诊断，实际前向仍对全部有效历史槽位做交叉注意力。

### 2.4 状态条件融合（保留原 MemoryVLA 门控）

- 不再造一套门控。只把 `p_t` 经轻量投影加入 V1 原门控输入或 logit：门控仍决定**历史影响多大**；检索模块决定**取哪段历史**。
- 新增分支优先保持 V1 行为。
- 保留原 V1 到 GR00T 动作专家的记忆注入路径，且**不得 detach / no_grad 掉与动作损失有关的路径**。即使动作专家参数冻结，仍需确认动作损失能回传到可训练的记忆融合参数。
- 为 V4 预留清晰接口：`state_feature`、`retrieved_memory`、`memory_gate`；本次不添加本体角色特征。

## 3. 训练数据与标签

### 数据原则

- 仅使用 **Task40 官方成功示教**。轨迹中“门还未打开”“袋子尚未放入”等时刻本身就是有效的**未完成状态**监督，不需要额外失败轨迹。
- 优先从仿真元数据、对象状态/场景状态或可重复回放得到状态标签。先核查真实可获得的字段和时间对齐方式；**拿不到的标签不得凭时间步或任务进度硬编**。
- 真值标签 `y_t` **只进入状态损失**；用于检索与写入的是模型预测 `p_t`，避免训练—推理不一致及标签泄漏。
- 状态标签与 `observation_t` 对齐，不能用 `t+1` 的动作结果给 `t` 的状态输入；历史只能来自 `≤ t` 的观测。
- 按**完整轨迹**划分训练/验证（默认 180/20；实际数量不足时按约 9:1），不得随机按帧划分造成同一轨迹泄漏；另用未参与训练的仿真初始条件做在线评估。

### 必须先交付的标签审计

- 实际读到的轨迹数、状态字段及其物理含义、每字段正/负帧比例、缺失率。
- 选取至少 3 条成功轨迹，给出“时间戳—观测—仿真标签—关键事件”的对齐示例。
- 若关键状态无法从官方示教或可重放仿真可靠获得，暂停进入验证训练并提交字段缺口与证据。

## 4. 训练设置：只运行一轮探索性验证训练

**可训练参数**：状态预测 head、状态条件 Query 投影、事件写入策略中若有的可训练参数、原 V1 中需要更新的记忆检索/融合门控参数。原则上冻结其他模块，明确打印可训练参数名称与数量。

**损失**：`L_total = L_action + λ_state × L_state`。

- `L_action`：沿用 V1 的动作预测/流匹配损失及动作维度定义，避免重新调整底盘/双臂权重混淆比较。
- `L_state`：有效状态字段上的 BCE（必要时按类别不平衡设权重）。
- `λ_state`：先看数个 batch 的损失和梯度量级，**一次性定标后锁定**，不做多轮超参扫参。
- 暂不增加事件损失、检索监督损失、门控伪标签损失。

**训练预算**：RTX 6000 Ada 单卡，先按实际显存与吞吐设定 batch、累积、精度。本轮上限为 2,000 个 optimizer steps，按工程预检结果在 1,000–2,000 步之间锁定。保留起点、验证最优和末尾的权重，供本轮对照及评估。训练分类与续训要求按 Skill 执行。

**训练前的必要门禁（不是额外科研实验）**：

1. 配置与权重能够正确加载，单 batch 前向/反向无 NaN、OOM；验证显存与吞吐。
2. 新增分支关闭/零初始化时输出应接近 V1（允许数值误差）；任务状态标签的时序不泄漏。
3. 通过一次短前反向检查：`L_state → 状态头` 有有限、非零梯度；`L_action → 状态条件检索/融合` 有有限、非零梯度。
4. 在同一个固定输入上，确认正常、清空和错配历史的动作输出可比较。若确认历史路径被截断，先修复再启动验证训练。
5. 确认在线检索只读已发生历史，状态条件来自 `p_t` 而非仿真真值。

如果单卡 OOM：优先调 microbatch/梯度累积、梯度检查点、可复用冻结特征缓存；记录变更。不得默默解冻 LLM 或将核心状态路径删除以换取跑通。

## 5. 集中评估：一次完成，不再单独训练消融

### 5.1 核心在线对照

- 在同一仿真版本、相同 action horizon、执行步数、初始条件/随机种子下，对比 **V1 基线 vs V2**。
- 固定 **12 组配对 Task40 初始场景**（V1 与 V2 各 12 回合）。优先核对 `Output/test_01/experiment_11/paired_trials.csv` 与 `eval_trials.csv`，V1 权重、完整任务起点、实例、种子和协议一致的回合直接复用，只补本轮缺失的配对。结果用于工程与方向判断，同预算 V1 续训对照留给后续独立实验。
- 逐回合记录：是否完成、最后到达阶段、门是否成功打开、袋子是否放入、门是否关闭、是否提前按按钮，以及视频和状态时间线。
- **主要错误定义**：门未成功打开/物品未放入时，策略却执行明显属于后续阶段的动作；需结合仿真真值和视频判断，不只用任务进度百分比。

### 5.2 固定观测下的记忆反事实（省 GPU，不跑三套全流程）

沿用 `Output/test_01/experiment_11/forward_replay_matched_14_full.json` 的 A/B/C 做法，优先复用可用的原始观测前缀、目标/供体锚点与回放入口。从可用锚点、留出轨迹和本轮评估记录选取**至少 100 个离线决策窗口**。复用 V1 已录的输入，按时间顺序用当前 V2 checkpoint 过一遍前缀，生成 V2 自己的历史记忆。固定当前观测、指令、感知记忆、随机噪声和模型权重，只改变认知记忆：

- `正常记忆`：按真实过去构建的记忆库；
- `空记忆`：按代码规定替换为空或零记忆；
- `错配记忆`：从其他轨迹/不匹配事件获取历史（控制库容量和特征尺度，记录构造方法）。

统计状态预测、历史槽位的注意力排名与事件相关性、门控值和动作输出差异。动作方向结合参考动作或在线后果分析。报告分别列出离线窗口数与有效独立回合数。

### 5.3 核心指标与判读

| 层次   | 指标                                      | 要回答的问题            |
| ---- | --------------------------------------- | ----------------- |
| 状态   | 各标签 Precision / Recall / F1、宏平均 F1、混淆矩阵 | 能否识别真实任务状态？       |
| 记忆   | 关键事件保留率、历史槽位注意力排名与事件相关性                 | 状态有没有改变写入与检索？     |
| 门控   | 门控随任务阶段分布、正常/空/错记忆的门控变化                 | 融合是否真的受状态影响？      |
| 动作   | 固定窗口动作差异、参考动作误差（按底盘/双臂/升降分项）            | 历史是否影响动作且方向正确？    |
| 在线任务 | 成功回合数/总数、错误阶段切换回合数、逐回合视频                | 是否改善 Task40 任务执行？ |

报告中不得只写 Loss 下降或状态头准确率上升就认定 V2 成功。**判断链条至少要完整呈现“真实状态—预测状态—写入/检索历史—门控—动作—执行结果”**。

## 6. 交付物与验收

通用记录与产物沿用 Skill 和仓库实验看板规范。本实验额外交付标签对齐审计、典型成功与失败的证据时间线，以及可复用的 V3/V4 接口说明。

### 验收分三级

- **工程合格**：状态标签可追溯、没有未来信息/真值泄漏、可复现运行，状态与动作两条梯度路径畅通，至少一轮训练和集中评估完整留档。
- **机制有效**：状态预测优于简单恒定状态基线；状态确实改变事件写入/检索与门控；动作对相关历史产生可测量的条件响应。报告量化结果，**不预设必须提升的数字**。
- **任务方向信号**：报告配对 Task40 中阶段误切与成功率的变化。结合本轮证据定位状态识别、检索、融合或动作专家利用记忆的瓶颈。归因结论留给同预算对照。

## 7. 停机条件与最终输出要求

V1 权重不兼容、仿真状态标签不可获得或时间错位、标签泄漏、动作损失无法回传到记忆路径、前反向不稳定时，暂缓验证训练并汇报证据。Agent 可修复工程阻塞。若解决方案涉及新方法或新数据，先由用户确认。

一轮验证训练及集中评估结束后，**按本轮预算收尾**，提交可复现材料与结论。

### 最后必须用四句话回答

1. **状态学会了吗？**（每项 F1 和错误类型）
2. **记忆变了吗？**（写入/检索/门控的实证）
3. **动作真的受影响了吗？**（反事实动作差异与方向）
4. **Task40 更好了吗？**（V1/V2 配对回合数与典型视频）

**本次定位**：先完成一个轻量、可以与 V1 公平追踪差异的 V2 闭环。V3 独立研究本体分角色记忆；V4 再研究“任务状态 × 本体角色”的联合检索和对动作专家更有效的条件注入。

# 资源与工作台执行细则

## 资源核对

开始前在各主机实际读取 `nvidia-smi --query-gpu=index,uuid,name,memory.total,memory.used,utilization.gpu --format=csv`、`nvidia-smi` 进程表及驱动/CUDA信息；以UUID与宿主机组成设备唯一键，核对用户声明的4×A100 80GB、2×RTX4090 48GB、1×RTX6000 Ada 48GB。特别注意驱动报出的显存与用户记录若不符，需在资源计划中同时记录两者，并按真实可用量进行OOM预算。不能假定多台主机的GPU编号是全局编号。

同时检查CPU核心、内存、共享内存、磁盘剩余/inode、checkpoint磁盘写速度、网络、工作台端口与进程、其他用户正在运行的服务、训练数据和仿真资产是否可见。

## 工作台作业流程

1. 定位现有工作台训练、推理、仿真服务的实际接口、启动语义和既有作业列表。禁止猜测API字段或新建平行私人调度系统。
2. 创建作业预览并核查：实验编号、数据、checkpoint、commit、配置hash、GPU UUID、GPU并发、端口、输出目录、任务队列及是否会干扰用户正式作业。
3. 经原工作台 `preview → start` 发起；立即登记job ID、服务会话、作业所有者、类别、启动时间和预期产物。
4. 执行期间通过工作台查询状态，按作业类型提供相应的控制。训练分类、短工程自检收尾、严格续训门槛见 Skill 主文。
5. 失败重试必须在同配置下保留原始错误，产生新的attempt ID；若修改影响科研条件的超参/环境版本，创建新实验谱系，不覆盖旧数据。

## 推理与仿真

- 4卡训练任务的A100首先保障DDP/FSDP 4 rank一致运行。把推理共置于A100之前，短程测训练steps/s、GPU高水位显存、推理QPS、P95时延及同步等待，只有收益明确且不触发OOM才采用。
- 依据 Skill 的设备用途核对工作台实时 `options`、网络、软件和模型可用性。Ada 串行或共卡承担多个阶段时，按显存峰值和吞吐合理排布。
- 两张4090各2环境为目标。仿真 worker 与模型会话一一关联或明确隔离；每个环境独立Memory reset、seed、输出目录、服务请求ID。先小规模负载测吞吐，再扩大并发。小显存/高CPU瓶颈时要降低并发并给出原因。
- GPU占用目标：A100单卡≥80%（80GB卡≥64GB），其余两类GPU默认≥70%是用户希望充分利用资源的运营指标，不是科研结果的验收替代物。用真实任务吞吐和失败率证明调度有效，解释不可达到的时段。

## 多任务同时运行时的安全续跑

- **不以整个A100集群空闲作为恢复前提。** 训练、诊断、推理及其他项目可以同机并行；工作台根据GPU UUID逐张测已有作业占用和峰值，满足`其他作业预计峰值 + 本作业FSDP峰值 + 安全余量 <= 实际可用显存`且实际吞吐可接受时，允许共享资源直接续跑。显存使用需按进程归属归档，不能把别的任务占用算成本实验贡献。
- 已锁定4卡同步训练时，仍要4个A100 rank一起恢复；**不改world size、effective batch、optimizer设置和训练谱系**。存在其他运行任务并不自动阻断4卡训练；如真实资源冲突则只排队该训练作业，其他互不依赖的实验继续执行，并由持续调度器自动发现可用窗口恢复。
- **A100目标>80%是资源利用目标，不是硬预分配，也不是保证每时刻都达标。** 80GB卡可目标64GB以上（可试80–90%区间），预留FSDP峰值/碎片/临时显存安全余量；共存后总占用达到80%不能据此假称本训练自己占用80%。出现OOM风险/吞吐退化要降并发或调整资源，保留原因和测量。
- 高优先级任务到来：先检查能否共享；仅共享不安全或用户明确要求让卡时，才在optimizer边界保存并由工作台暂停当前训练，等达到安全条件后**自动严格续训**。不能杀死其他任务、不能由Agent随意占满全部显存。

## 持续调度与安全

- 通过现有工作台排队依赖任务：训练checkpoint完成 → 权重重载检查 → 已获用户确认的仿真闭环 → 报告整合。不自动派发离线记忆诊断或Probe；遵循SKILL.md中的用户长期要求。任何一个环节失败，不能假装后续依赖已经满足。
- 调度器与watchdog要可持久重启，保存 `watchdog_state.json`、追加式 `watchdog_log.jsonl`。记录每次巡检时刻、动态周期、真实进度变化、失败原因、自动恢复动作和重试上限。
- 不自动终止其他用户/其他实验作业；不无意义占用显存；不随意清理旧checkpoint。磁盘不足先整理可安全删除的临时缓存，经用户规则确认后再执行。
- 当工作台不支持真正的自动化暂停/续训时，明确阻塞，先接入工作台功能或请求用户批准；不能报“已支持”。

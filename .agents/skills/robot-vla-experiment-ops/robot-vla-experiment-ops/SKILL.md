# 工作台实验执行

本 Skill 是通用执行规则的唯一入口。任务书保存研究选择，工作台手册保存接口，代码校验身份。实验配方不在此处重复维护。

## 读取顺序

先读本 Skill 和仓库 `docs/workbench/agent.md`。接续实验还须读对应 `task.md`、最新 `workflow/plan-vNNN.json`、`progress.md`，并核对实际作业和证据。按操作读取：

- 新训练、权重选择、版本与续训：[身份与命名](references/checkpoint-naming.md)。
- 资源调度、入口排错：[硬件与工作台](references/hardware-workbench.md)。
- 训练及暂停恢复：[训练与续训](references/training-resume.md)。
- 推理、闭环、结果验收：[评估与报告](references/evaluation-reporting.md)。
- 历史方法差异只在目标属于对应任务时，按[身份与命名参考中的历史上下文](references/checkpoint-naming.md#已有方法上下文)核对，再读取对应 `task.md`、计划和实际配置；不得把历史选择推广到新实验。

## 授权与研究选择

1. 用户明确指令（含已确认的长期要求）优先于任务书和 Skill 默认流程。任务书不能覆盖用户要求。已确认方案内的工程修复、排队和续跑继续执行，不重复索取许可。
2. 创建或实质改变实验任务书前，先通俗说明目标、初始化权重、继承/重置模块、数据与标签、训练量、闭环起点、每模型回合数、终止条件和结果指标，等用户确认。改变这些研究选择时重新确认；“继续跑”不授权改变训练起点。
3. 未指定的科学配置从已锁定方法、源码和配置核实。不把示例当通用超参，不自行改变 LoRA、冻结范围、训练目标、数据划分或有效 Batch。登记方法版本不等于实验获批。
4. 效果交付只呈现仿真闭环。不派发离线记忆诊断、Probe、正常/空/错历史替换、注意力/门控差异或动作 MAE 独立评估；具体故障所需内部检查可以做，已有历史证据保留。
5. 标签检查限于正确使用数据：核对对象、时间对齐、可读性并抽查关键变化。全量导出不等于必须全量回放认证；发现具体缺失/错位再定位，不能擅自删掉关键状态目标。

## 启动前锁定身份

- 身份由四个独立维度构成：方法版本、`testNN`、`expNN`、`runNNN`；checkpoint 再带累计 optimizer `stepNNNNNN`。例如 `V_2_1` 对应 `v2_1__test02__exp01__run001`。实验编号永远不能生成或递增模型版本。
- 新方法/小版本须先说明相对父版本的科学差异并获用户确认，再在 `train/run_identity.py` 登记；`options.model_versions` 是当前可启动版本目录。`V_2_2`、`V_2_1_1` 等不能按实验编号、日期或代码提交自动推导。登记不等于实验获批。
- 每个新训练必须显式传已登记的 `version` 和完整 `run_id`；preview/start 任一身份、版本一致性或唯一性校验失败时停止并修正源字段。身份缺失时询问，不用默认版本/编号、不改用旧入口绕过校验。
- 新 seed、独立初始化/重训或影响可比性的配置使用新的 `runNNN`；同一训练的暂停恢复、重派、进程重启和增加已批准总步数保留原 `run_id`，另记 attempt/resume event。工程修复记录源码 revision/hash，不自动增加方法版本。
- 历史路径、作业 ID 和 checkpoint 保持稳定。只对证据已核实的错误身份添加只读映射并保留原值；旧记录缺少测试/实验编号时，不推测它们来生成新分支 ID。
- 推理和评估必须绑定确切 checkpoint ID、路径和 hash；`latest` 只能解析到实体 checkpoint，不能作为权重身份。

## 工作台与资源

1. 状态/方案使用只读 GET。先查 services、options、jobs，按宿主机及GPU UUID核对实时容量、作业、权重、数据与入口，优先复用匹配结果和服务。
2. 训练、推理、仿真统一经现有工作台：同一配置 `preview → 资源核对 → start`。身份、预算、GPU、源码和输出须与任务一致；提交超时先查jobs再决定重试，不重复提交或另建私人调度器。
3. 提交后核对 job ID、状态、实际输出和日志，记录设备、源码commit/hash、配置、数据、初始化权重和产物。预览成功不等于提交，提交不等于实跑，实跑不等于完成。
4. 设备声明为4×A100 80GB、2×4090 48GB、1×RTX 6000 Ada 48GB，启动时实测复核。四卡任务必须同一个作业使用四个真实A100 rank，保留有效Batch。其他任务在跑不构成全局等待理由；安全时共存，不抢占现有作业。
5. 仿真目标为两张4090各2环境；按实测显存、CPU、端口、推理QPS和回合吞吐调整。每环境独立策略/记忆会话、seed及产物。Ada可按能力补充。
6. 有真实待办时A100显存目标每卡≥80%，4090/Ada≥70%。正确性、不干扰已有作业和有效吞吐优先；不空占显存或改变科学配置凑数。容量不足时排队该作业，继续其他已授权独立任务。

## 训练、推理与闭环

- 训练前验证真实batch前后向、预期模块进入optimizer、有梯度及参数更新、保存重载。按当前方法配置锁定LR、优化器、冻结范围、精度、horizon、采样和保存周期，记录 `world_size × microbatch × accumulation`、有效Batch和seen samples。
- 训练类别依用途和已批准预算，不设通用“至少5000步”门槛。工程自检最多100 optimizer steps；终态先归档证据，核对归属/依赖后，经工作台清理专属临时记录和产物。
- 计划累计超过2000 optimizer steps必须在同工作台验收严格暂停/恢复：模型、optimizer、scheduler、适用scaler、各rank RNG、采样位置、累计step和元数据完整；暂停释放资源，同run恢复并真实继续更新。仅重载权重不算严格续训。
- 记录Loss、LR、梯度、参数变化、步耗时、吞吐、显存及错误。Loss下降不等于闭环收益。step为累计optimizer更新数，不是microstep或恢复后的局部计数。
- 推理加载确切checkpoint及兼容源码；记忆用本权重自己的网络和原始顺序观测重建，不借用别的权重memory tensor。
- 闭环固定任务、实例、seed、控制器、动作窗口、步数、成功判据和恢复协议。画面在已验证容差内可近似一致，不默认加逐像素门槛。
- 按独立回合/实例统计成功分子、有效分母、置信区间；区分模型动作、实际动作、物理真值、人工判定。在线阶段预测与同一时刻真值对照，交付视频/时间线。官方未追加训练权重仅作性能参考；记忆净收益需同起点、数据和预算的无记忆对照。

## 监管与交付

- 计划和task/progress遵循 `docs/workbench/agent_experiments.md`；主线、依赖、验收变更新增计划版本并提交。Skill/工作台维护不伪造实验任务或GPU作业。
- 长任务接现有队列、回调或supervisor，状态落盘、可重启、去重。事件驱动优先，定时巡检兜底；运行且有待办时实质巡检原则上不超过30分钟；有待办却连续空闲超过10分钟时调查/派发。记录下次检查时间及理由，不靠单会话长sleep。
- NaN、错误谱系、身份不明、重复OOM时定位并留证，必要时经工作台暂停问题作业，不悄改科学配置。失败如实记录。
- 每批评估结束，确认无运行/排队/已安排续跑依赖后，经工作台释放本次推理服务；不停止归属不明服务。
- 按完成/部分完成/阻塞/未执行验收，报告真实计数、job ID、checkpoint、视频及证据路径。无有价值待办时结束，不为占用率生造实验。任务书见[模板](templates/experiment-task-template.md)。
